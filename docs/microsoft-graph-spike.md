## Phase 11 rows (calendar self-only writes and RSVP)

Phase 11 is built ahead of the spike against documented Graph and Google Calendar behaviour and the same synthetic stubs as phase 10, which now also take writes and run the shared write conformance suite (`providertest.RunWrite`). The plan gates this phase on `calendar-preconditions` passing; under the stack instruction it is built on the documented behaviour, and nothing here may be enabled until that row is VERIFIED. The tools write only events that involve nobody but the account itself; an event with any other attendee returns `invites_not_enabled` until phase 12. Microsoft stays behind `email.microsoft.enabled=false` and calendar behind `email.calendar.enabled=false`.

Every update and delete reads the event, classifies it on the union of its attendees now and after the change (an event someone else organizes is never self-only), and writes conditionally on the version it read. A 412 re-reads and re-classifies; if attendees appeared the call stops, otherwise it retries once at the new version. A provider call with no version is refused before any request.
